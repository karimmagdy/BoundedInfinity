\section{Related Work}
\label{sec:related}

BIC sits at the intersection of three established research lineages.
Rather than claiming to be ``the first'' system to bound agentic
memory, we explicitly position BIC against each lineage and identify
the specific gap it fills.

\paragraph{Lineage 1: Operating-system memory management.}
The systems community has studied bounded-memory caching for over
half a century: B{\'e}l{\'a}dy's optimal page-replacement
algorithm~\citep{belady1966study}, Denning's working-set
model~\citep{denning1970wset}, and the standard LRU/LFU/clock
heuristics catalogued in modern OS
textbooks~\citep{tanenbaum2014modern}.  These mechanisms manage a
fixed pool of physical pages or cache lines, evicting victims to
secondary storage (swap) or simply discarding them.  BIC inherits the
fixed-capacity discipline and the $\Oh(M)$ memory bound from this
tradition, but differs in what eviction \emph{means}: classical OS
eviction either pages an exact copy to disk (lossless but
disk-bound) or discards (lossy and unrecoverable).  BIC compresses
\emph{semantically} via hierarchical summarization, exploiting the
fact that LLM agent state is natural-language text that admits lossy
but task-preserving compression.  This is what makes BIC suitable for
the agent setting where reloading from disk is impractical (each
``page'' is a full LLM context that cannot be transparently swapped
mid-reasoning).

\paragraph{Lineage 2: Streaming and sketching algorithms.}
The streaming-algorithms literature provides bounded-space
substitutes for unbounded computation: count-min
sketches~\citep{cormode2005cm}, reservoir
sampling~\citep{vitter1985reservoir}, space-saving for heavy
hitters~\citep{metwally2005spacesaving}, HyperLogLog for
cardinality~\citep{flajolet2007hyperloglog}, and sliding-window
algorithms~\citep{datar2002sliding}.  BIC's deterministic Cantor
addressing and Hilbert-curve locality preservation are conceptually
similar to these sketches: both compress an arbitrary input domain
into a fixed slot space using a closed-form mapping, and both rely
on structural properties of the mapping (universality for sketches,
parent--child locality for Cantor) for correctness.  The key
difference is data shape: streaming sketches operate on flat,
unstructured data streams, whereas BIC operates on tree-structured
agent state with explicit parent--child semantics that drive both
addressing and summarization.

\paragraph{Lineage 3: RAG and LLM-memory systems.}
A complementary line of work equips LLM systems with external
long-term memory accessed through retrieval.
MemGPT~\citep{packer2023memgpt} (now Letta) introduces an
OS-inspired paging system for a \emph{single} agent's context window.
A-MEM~\citep{amem2025} treats memory management itself as an agentic
task in which an LLM autonomously decides what to remember.
Voyager~\citep{wang2024voyager} accumulates a growing skill library
across episodes.  AutoAgents~\citep{wang2024autoagents} dynamically
generates specialized agents and stores their personas.  The ICLR
2026 MemAgents Workshop~\citep{memagents2026} surveys this rapidly
moving area.  All of these systems retrieve external content (vector
DB or skill library) into a small active context.  BIC is
\emph{complementary}: it manages the internal active working set
across recursively spawned sub-agents, the very thing that fills the
context the moment a RAG retrieval succeeds.  A practical deployment
would compose BIC (working-set memory bound) with a RAG memory
(long-term external knowledge) rather than choose between them.

\paragraph{Where BIC fits.}
None of the three lineages above directly target recursive multi-agent
state.  OS paging assumes a flat virtual address space and cheap
swap; streaming sketches assume flat data streams without
parent--child structure; RAG memory assumes external knowledge rather
than internal active state.  BIC is a specific instantiation that
combines (a)~the deterministic addressing of streaming algorithms
(Cantor pairing on tree positions), (b)~the semantic compression of
LLM-based summarization, applied to (c)~the recursive agent
state-management problem that none of the prior systems target
directly.  We make no claim of being the \emph{only} possible such
combination---only that this particular combination admits formal
$\Oh(M)$/$\Oh(\log N)$ guarantees and works on real Gemini-2.0-flash
agent traces.

\paragraph{Multi-agent LLM frameworks.}
LangGraph~\citep{langgraph2024} models agent workflows as state
machines with checkpointing but provides no memory bound.
AutoGen~\citep{wu2023autogen} enables flexible multi-agent
conversations; CrewAI~\citep{crewai2024} and
CAMEL~\citep{li2023camel} orchestrate role-based agent teams;
MetaGPT~\citep{hong2023metagpt} assigns software-engineering roles.
All store every agent state in unbounded Python data structures.
Our work is orthogonal: BIC can serve as the memory layer beneath any
of these frameworks.

\paragraph{Memory management for LLM agents.}
MemGPT~\citep{packer2023memgpt} (now Letta) introduces an
OS-inspired paging system for a \emph{single} agent's context window,
moving segments to disk when the context is full.  It does not address
multi-agent hierarchies or provide formal memory bounds.  We
implement a Tiered baseline mirroring MemGPT's hot/cold architecture
(\S\ref{sec:stress}); BIC outperforms it by $32\times$ on
reconstruction quality at scale.
Reflexion~\citep{shinn2023reflexion} compresses a single agent's
episodic memory into a verbal summary for the next trial.
Generative Agents~\citep{park2023generative} maintains an
ever-growing memory stream with retrieval over it.
None of these systems bound total memory across an agent swarm or
provide reconstruction guarantees for evicted states.

\paragraph{Recent memory management for LLM agents.}
The growing interest in long-running LLM agents has spurred recent work
on agent memory management.  The ICLR 2026 MemAgents
Workshop~\citep{memagents2026} brought together researchers addressing
memory architectures, retrieval mechanisms, and resource management for
LLM-based agents, highlighting the timeliness of this problem.
A-MEM~\citep{amem2025} proposes an agentic memory system where an LLM
agent autonomously decides what to remember and how to organize its
memories, treating memory management itself as an agentic task.
Both lines of work focus on the \emph{quality} and \emph{organization}
of individual agent memories, whereas BIC addresses a complementary
\emph{systems} challenge: bounding the total cache memory consumed by
an entire swarm of agents while preserving retrievability of evicted
states through hierarchical summarization.  BIC's cache management
layer could be combined with richer per-agent memory strategies such
as those explored in A-MEM.

\paragraph{Streaming and sketching algorithms.}
The streaming-algorithms community provides tools for processing
unbounded data in bounded space: Count-Min
Sketches~\citep{cormode2005cm}, HyperLogLog~\citep{flajolet2007hyperloglog},
and sliding-window algorithms~\citep{datar2002sliding}.  These
structures are designed for aggregate statistics (counts, cardinalities)
over data streams, not for managing structured agent states with
parent-child relationships and reconstruction requirements.  BIC
borrows the principle of bounded-space processing but applies it to
hierarchical agent-state management with summarization.

\paragraph{Cache-efficient computation and space-filling curves.}
Hilbert curves are widely used in database
indexing~\citep{lawder2000hilbert} and cache-oblivious
algorithms~\citep{frigo1999cache} to improve spatial
locality.  The Cantor pairing function provides a bijection
$\Nat \times \Nat \to \Nat$ used in computability theory and database
design.  We repurpose both for a novel application: mapping
tree-structured agent hierarchies to cache slots (Cantor) and
clustering agent states for locality-aware eviction (Hilbert).

\paragraph{Hierarchical summarization.}
Tree-based summarization appears in document
summarization~\citep{wu2021recursively} and retrieval-augmented
generation~\citep{raptor2024}.  Our hierarchical summarization differs
in that it is \emph{eviction-driven}: summaries are created lazily
when cache pressure forces eviction, and the summarization chain
doubles as the reconstruction path for queries about evicted agents.
